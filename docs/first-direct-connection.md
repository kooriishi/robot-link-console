# 第一次直连 Linux 机器人

本指南适用于 RoboLink **v0.3.0 Ubuntu 22.04 amd64 测试候选版**。有线拓扑是：开发机和机器人用一根网线直接相连，不经过路由器或交换机。机器人必须已开机，并由固件或你信任的本地方式启用 SSH；网线本身不会替两端分配 IP。

> 这是供真实设备试用的测试候选，不是 GitHub Release。请只安装项目负责人提供的 `.deb` 文件；完成实机测试并获得明确批准之前，不把它当作正式发布版。

## 1. 安装并启动 RoboLink

1. 在 Ubuntu 22.04 amd64 上找到收到的 `RoboLink_0.3.0_ubuntu22.04_amd64.deb` 文件。
2. 双击该文件，用“应用中心”或“软件安装”打开，选择“安装”，并在 Ubuntu 弹出的系统窗口中确认。也可以在终端运行 `sudo apt install ./RoboLink_0.3.0_ubuntu22.04_amd64.deb`。
3. 安装完成后，在系统应用列表中打开 **RoboLink**。RoboLink 安装在开发机；机器人不需要安装该程序。

如果系统提示 `libwebkit2gtk-4.1-0` 版本不足，请先用 Ubuntu“软件更新器”安装 22.04 更新，或打开终端运行 `sudo apt update` 后重试安装。RoboLink 需要 WebKitGTK 4.1 至少 2.38。不要从不明网站单独下载系统库；如果更新后仍提示缺少桌面依赖，请确认系统是 Ubuntu 22.04 amd64，并让项目维护者检查软件包依赖。

## 2. 插线并扫描设备

1. 用网线直连已开机的机器人和开发机。打开 RoboLink 左侧的“网络与 Wi‑Fi”页面。
2. 查看“开发机有线网卡”卡片。标为“物理链路已连接”的接口检测到网线；扫描会同时监听所有已连接的物理网口，因此不必猜应该选哪张网卡。点击卡片可以查看本机接口名称、IPv4 和 MAC。
3. 在“SSH TCP 端口”保留 `22`，除非机器人实际使用其他端口，然后点“扫描所有已连接网口（8 秒）”。
4. 首次被动监听或配置临时地址时，Ubuntu 会弹出系统授权窗口。确认这是由 RoboLink 发起的网络操作后，输入你自己的 Ubuntu 登录密码。授权只用于读取 ARP 或执行你已确认的单个网口地址操作；不会配置 Wi‑Fi、DNS、DHCP 或默认网关。
5. 结果会列出候选 IPv4、发现它的本机网卡、对端 MAC、ARP 证据类型，以及所选 TCP 端口状态。请先对照机器人的标签、说明或可信控制台确认 IP/MAC；ARP 候选只是网络证据，不是设备身份验证。

RoboLink 监听 8 秒内实际到达网卡的 ARP 报文，不会扫描整个 IPv4 地址段，也不会主动唤醒静默设备。它只把 ARP 源 IP 作为地址候选；源地址是 `0.0.0.0` 的 ARP 探测则显示其目标 IP。若机器人在扫描期间不发 ARP，即使网线已通，也可能没有结果。此时查机器人的已知地址，使用页面里的“手动添加 IP / 主机名”，或先按机器人说明让它发起网络通信。

## 3. 必要时给开发机添加一个临时地址

如果找到了机器人的 ARP 候选，但显示“当前路由未到此网口”，说明开发机目前没有经这张直连接口到达机器人的 IP 路径。可以在该结果旁点“临时配置本机 IP”。

例如机器人说明明确写着 `192.168.127.10/24`，可以把开发机地址设为 `192.168.127.1/24`。RoboLink 默认会按这个常见例子预填 `.1/24`，但 **ARP 不携带子网掩码，`/24` 只是可编辑假设**：如果机器人使用其他掩码或固定地址，请按设备文档填写与机器人同网段、且未被占用的本机地址。

点“确认并临时添加”前，请再次核对网卡和地址。RoboLink 会检查地址格式、网段、已存在的地址、重叠路由，并发送重复地址探测；发现冲突或无法确认路由时会拒绝添加。系统授权成功后，它只给选定的物理网卡加这一条 IPv4 地址，不会更改开发机的默认路由、DNS、Wi‑Fi、DHCP 或防火墙，也不会修改机器人端配置。

默认选中“SSH 会话结束后清理”。这条地址会在 SSH 会话结束时尝试自动移除。也可以取消勾选让地址保持；保持模式不会在 SSH 断开后自动删除，直到你在同一页逐条或点“全部清理”。如果应用或电脑意外关闭，地址可能暂时留在本机；重新打开 RoboLink 后，仍可在地址列表中清理。Ubuntu 重启通常会清除这类临时地址。

## 4. 添加机器人并核对 SSH 身份

1. 在候选结果点“添加为机器人”。地址、端口和用户名 `sunrise` 会预填；请按你的机器人实际 SSH 用户名修改，确认端口仍与设备相符，然后保存。
2. 点“连接机器人”。第一次连接时，RoboLink 会显示 SSH 主机密钥指纹。扫描结果、MAC 地址或端口开放都不能证明对方就是你的机器人。
3. 请在机器人本地可信控制台或制造商提供的可信渠道核对指纹。例如机器人使用 ED25519 主机密钥时，可在机器人端运行：

   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

4. 只有指纹与 RoboLink 显示的一致时，才选中该指纹并确认。若以后指纹变化，先查明是否重装、更换设备或存在中间人风险；不要为了连上设备而直接接受新指纹。

SSH 密码由系统 OpenSSH/终端交互处理；RoboLink 不保存 SSH 密码。首次登录之后，服务、机器人 Wi‑Fi、蓝牙和音频操作都通过当前 SSH 用户执行；RoboLink 不会自动在机器人上运行 `sudo`。

## 扫描不到或连不上时

- **没有“物理链路已连接”：**确认机器人电源已开、网线两端插牢，并换一个开发机物理以太网口测试。
- **扫描没有候选：**机器人可能在 8 秒内没有发出 ARP。核对机器人已知 IP，使用手动添加，或先按设备说明启动网络通信；本扫描不会穷举静态 IP。
- **有候选但 TCP 端口未确认：**可能是本机还没有同网段路由、端口不是 `22`、机器人 SSH 服务未启动或防火墙拒绝。可先用“临时配置本机 IP”，再按设备实际端口重新扫描。
- **TCP 可达但 SSH 失败：**确认 SSH 用户名、端口和机器人 `sshd` 状态。TCP 可达不等于 SSH 登录成功。
- **SSH 指纹不匹配：**先在可信机器人控制台核对当前公钥。不要直接接受不认识的密钥。
- **不再需要临时地址：**在“网络与 Wi‑Fi”页面找到“RoboLink 添加的地址”，逐条点垃圾桶，或点“全部清理”。清理失败时条目会保留，方便重试。
- **授权窗口没有出现：**请使用 Ubuntu 桌面会话，并确认系统安装了包依赖中的 polkit 组件。不要改成以 root 身份启动整个 RoboLink。

已知边界：当前流程只支持 IPv4 和一次一个 TCP 端口；不提供 DHCP server、不扫描整个网段、不自动配置机器人 IP、不改开发机的默认路由，也不支持 IPv6 自动发现。网线直连不需要 Internet，但两端仍必须有可互通的地址，且机器人 SSH 服务必须已启用。
