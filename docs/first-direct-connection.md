# 第一次直连 Linux 机器人

适用于 **RoboLink v0.4.2 · Ubuntu 22.04.5 amd64 测试候选**。开发机和机器人用一根网线直接相连，不经过路由器或交换机。机器人必须已开机并启用 SSH。所有发现和本机配网操作都在 GUI 中完成，不需要手动执行抓包或配网命令。

> 本包尚未做真实机器人硬件验收，也不是 GitHub Release。请先试用并反馈结果，明确批准后才考虑正式发布。单元测试、构建或模拟界面检查不能代替真机测试。

## 安装并启动

在 Ubuntu 文件管理器中双击 `RoboLink_0.4.2_ubuntu22.04_amd64.deb`，用“应用中心”或“软件安装”安装，然后在系统应用列表打开 **RoboLink**。安装在开发机即可，机器人不需要安装。

若安装器提示桌面依赖缺失或 WebKitGTK 版本不足，先使用 Ubuntu“软件更新器”。不要从不明网站下载系统库，也不要以 root 启动整个 GUI。安装包带有受限网络 helper；仅在你选择的操作需要抓包或修改本机网络时，通过 Ubuntu 系统授权窗口执行。

## 1. 选择网卡与发现策略

插线后打开“网络与 Wi-Fi”。物理链路已连接表示网卡 carrier 已检测到信号，并不代表已有可用 IP 或 SSH。可以扫描所有物理有线接口，也可明确指定接口；断开的接口会跳过。

在策略区域选择适合的发现方式。建议先用默认选项观察，只有确实需要时才启用 DHCP Server。

| 选择 | 适合什么情况 | 如何理解结果 |
|---|---|---|
| 主动 ARP 扫描（推荐，默认开） | 板子已开机、静态 IP 未知且不主动发包 | 对常见开发板网段发送 ARP 地址探测，板子为自己的 IP 应答即列为“主动 ARP 扫描应答”。深度扫描覆盖整个 192.168.0.0/16 与 169.254/16。 |
| ARP 被动监听 | 静态 IPv4 设备发送 ARP 请求/应答、免费 ARP 或地址探测 | 普通源地址证据较强；`0.0.0.0` 探测中的目标只是拟使用地址，不等于已配置成功。一般 ARP 目标不认作设备 IP。 |
| DHCP 被动监听 | 开发板正在请求 DHCP 地址 | 请求的 IPv4 是候选；无地址的 Discover 会提示可选 DHCP。也读取本应用的 DHCPACK 日志缓存以免错过握手，缓存不代表设备仍在线。监听本身不会启动服务器。 |
| IPv6 Neighbor Discovery | 设备发送 IPv6 邻居发现/地址检查报文 | 区分已观察源地址和 DAD 候选；不把任意被查询目标当成发包设备。 |
| mDNS | 设备发送 mDNS 本地发现报文 | 使用报文源 IP/MAC，不把报文中广告的第三方记录当作已确认设备。 |
| 候选 ARP 验证 | 已收集到 IPv4 候选，需要确认该接口是否收到对应 ARP 应答 | 只针对候选，不扫描整个 IPv4 子网。未应答不等于离线。 |
| ICMP 辅助验证 | 有对应接口路由，希望额外检查 Ping | 失败可能是设备禁用 ICMP，不能直接判为不可达。 |
| 单个 TCP 端口 | 检查 SSH 所用端口是否可达 | 默认 22，可按设备实际端口修改。未选择/路由不符/未探测与端口探测失败分开展示。 |
| IPv4 Link-local | 设备使用 `169.254/16` | 收集报文与接口邻居，不穷举 65,536 个地址；必要时确认添加本机 `/16` 地址。 |
| IPv6 Link-local | 设备使用 `fe80::/10` | 结合报文、受限的 IPv6 全节点探测与邻居信息；该选项会发送链路本地探测报文，不响应不代表离线。结果必须保留 `%本机网卡名`，SSH 也使用此 scope。 |

点击扫描后，先完成 Ubuntu 系统授权，再等待约 8 秒主动扫描、监听和附加验证。结果显示 IP、MAC、来源网卡、证据类型及独立验证状态。TCP 验证只在确认路由经过该接口时进行，避免误走 Wi-Fi 或其他网卡。

任何策略都无法保证发现任意静默的未知静态 IP。若没有结果，请确认设备在发网络报文，或按固件说明查已知地址并在 GUI 手动添加；不要把“没有发现”理解成“网卡授权失败”。

## 2. 必要时附加本机 IPv4

候选显示路由未就绪时，可点结果旁的“临时配置本机 IP”。例如机器人明确使用 `192.168.127.10/24`，本机可选未占用的 `192.168.127.1/24`。

**ARP 不携带真实掩码，普通地址预填的 `/24` 只是可修改的假设。** 请优先参考机器人文档。IPv4 Link-local 候选使用 `/16`。IPv6 候选不使用此 IPv4 配置按钮。

确认前核对网卡、地址、前缀和模式。helper 检查现有地址、路由重叠和重复地址后，仅为选定物理有线接口附加一条地址，不覆盖现有地址，不改默认路由、DNS、Wi-Fi 或机器人端配置。冲突时拒绝添加。

默认在 SSH 会话退出时尝试清理；保持模式则保留到手动清理。地址归属会保存，异常退出后重新打开应用仍可查看和清理。清理失败条目会保留，不会假称已成功移除。网络重连可能由 NetworkManager 重置临时地址，此时应刷新状态并重新核对，不能把旧记录当作地址仍然存在。

## 3. DHCP Client 设备：明确启用 DHCP Server

静态 IP 已找到时通常不需要这一步。DHCP 被动监听不是 DHCP Server，服务器默认不会随扫描启动。

1. 确认网卡只用一根网线直连机器人，**不要在办公 LAN、路由器或交换机网络上启动**。
2. 在 DHCP 区域选择接口，设置未占用的私有 `/24` 本机地址，默认 `192.168.77.1/24`。地址池使用同网段的 `.10–.200`，本机地址不要落入池中。
3. 阅读确认提示，点击启动并完成系统授权。应用会先检查冲突，创建本应用专属服务和临时地址。
4. 让开发板的 DHCP Client 请求/续租地址，然后重新扫描。DHCPACK 日志缓存候选不代表当前租约仍有效或 SSH 已开启，仍要检查实际 SSH 端口和主机指纹。
5. 不再使用时点击停止/清理。应用只停止自身记录且 PID 身份匹配的进程，只移除自身附加的地址；不会终止原有 dnsmasq 或删除用户 NetworkManager 连接。

此模式**仅供直连 SSH**：不下发默认网关或 DNS，不共享 Internet，不改开发机转发和防火墙。这样可降低影响机器人 Wi-Fi 上网的风险，但固件可能有特殊 DHCP 行为或旧租约，不能替机器人保证 Wi-Fi 路由始终不变。

“状态未查询”不代表服务一定关闭。应用异常退出后，通过“查看状态”识别本应用遗留的服务，再停止清理。服务和地址记录位于受保护的运行目录；重启后运行目录与临时配置通常会消失。当前不实现互联网共享模式。

## 4. 添加目标并核对 SSH 身份

在候选上选择添加为机器人，检查用户名和端口。RDK 例子可用 `sunrise`，但请按自己的镜像设置。IPv6 Link-local 地址应包含 `%接口名`，不要删掉。

首次连接时，GUI 会显示主机密钥指纹。请通过机器人可信本地控制台或厂商可信渠道核对，再确认固定一把 key。以后指纹变化应先核实重装或换设备原因，不要为了连接而跳过警告。IP、MAC、邻居缓存和端口开放都不能证明设备身份。

SSH 密码由 OpenSSH 交互处理，RoboLink 不保存。通过验证后，服务、机器人 Wi-Fi、蓝牙和音频操作使用当前 SSH 用户，不自动在机器人上提权。

## 失败提示如何区分

| 提示类别 | 含义与处理 |
|---|---|
| 系统授权未完成、未通过或已取消 | 操作没有执行。重新点击，并在 Ubuntu 系统授权窗口完成认证。 |
| 授权代理或网络助手无法启动 | 检查 Ubuntu 桌面会话、polkit 和候选包是否完整安装；不要用 root 运行整个 GUI。 |
| 网络操作失败（授权已通过） | 阅读具体原因：链路拔出、接口消失、地址/路由冲突、依赖缺失等。不是密码被拒绝。 |
| 部分接口已跳过 | 插拔发生在枚举与抓包之间或接口已断开，其他可用接口仍继续。 |
| 候选但 TCP 未确认 | 检查对应接口路由、实际 SSH 端口、sshd 与防火墙。ICMP 失败不能替代 TCP 结论。 |
| DHCP 启动被拒绝 | 可能存在原有服务、UDP 67 占用、路由/地址冲突；应用不会为启动自己的服务而杀掉现有服务。 |

## 建议的真机试用顺序

先用原来已验证的 RDK 静态地址流程：开发机与板子直连，选择 ARP，观察 `192.168.127.10` 与正确 MAC/网卡，确认临时地址，检查自定义/默认 SSH 端口，再核对指纹登录。分别测试会话退出清理和保持后手动清理，并确认开发机 Wi-Fi 没有变化。

然后再逐项测试 DHCP Client 板子、IPv4 Link-local、IPv6 Link-local、mDNS/ND、禁用 ICMP 但 SSH 正常、授权取消/重试、扫描中拔掉一张网卡、应用异常退出后清理。多网卡先测试互不重叠的子网；重叠子网、相同目标 IP 的策略路由/Network Namespace 不在本阶段支持范围，冲突应拒绝而不是自动改路由。
