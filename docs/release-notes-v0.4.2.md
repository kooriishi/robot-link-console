# RoboLink v0.4.2 测试候选

## 修复：一根网线直连时扫描不到开发板 IP

**原因**：v0.4.x 的发现完全依赖被动监听。开发板开机后若不主动发 ARP / DHCP / mDNS 报文（静态 IP 板子很常见），8 秒监听窗口里什么也收不到；只有开发板重启时会发 gratuitous ARP，所以“只有重启时能扫到”。原来的“主动 ARP 验证”也只验证已经被动发现的候选，无法产生新候选。

**修复**：网络助手新增 **主动 ARP 扫描**（默认开启）：

- 以 `0.0.0.0` 为源地址发送 RFC 5227 ARP 探测。Linux 内核会为自己接口上配置的任意 IP 应答这种探测，因此开发机网口 **不需要先配置 IPv4**，开发板也不需要重启或主动发包。
- 默认覆盖：扫描网卡自身的网段，以及约 30 个常见开发板 / 系统默认 /24（192.168.1、192.168.0、192.168.127（RDK）、192.168.137、192.168.55（Jetson）、192.168.7、10.42.0（NetworkManager 共享）等）。
- “网线直连深度扫描”（默认开启）额外覆盖整个 `192.168.0.0/16`；勾选 IPv4 Link-Local 时再覆盖 `169.254.1.0–169.254.254.255`。约 13 万个 42 字节帧在 8 秒窗口的前约 5 秒内匀速发出，期间同时接收应答。
- 承载默认路由的网卡（看起来接的是路由器 / 局域网）自动只扫描本机所在网段，并在发现提示中说明，避免在共享网络上大量广播。
- 应答必须是发给本机 MAC 的 ARP Reply，结果标为“主动 ARP 扫描应答”，ARP 可达直接标记为“可达”。
- 抓包 socket 设置 `PACKET_IGNORE_OUTGOING` 并扩大接收缓冲，避免大量自身发出的帧挤掉开发板的应答。

找到 IP 后，流程与之前一致：点击“临时配置本机 IPv4”让开发机与开发板同网段，再添加为 SSH 主机并核对指纹。

在容器中用 veth + network namespace 模拟“开发板”（不主动发包的静态地址 192.168.127.10、192.168.213.10、169.254.250.7）验证：默认扫描找到 192.168.127.10，深度扫描三个地址全部找到。仍需真机验收。

## 优化：页面切换卡顿

- 所有 Tauri 命令改为在后台线程池执行（`#[tauri::command(async)]`）。之前同步命令在 GUI 主线程上运行，每次切页触发的 SSH 查询（服务、Wi-Fi、蓝牙、音频）都会让整个窗口卡住直到远端返回。
- 远端页面数据按“目标 + 页面”缓存 30 秒，来回切页不再重复执行 SSH 查询；点“刷新”、切换目标或 SSH 断开时立即失效。
- 页面数据加载不再占用全局“忙碌”状态，加载期间其他按钮可用，刷新按钮显示“读取中”。

## 版本

package.json、tauri.conf.json、桌面程序与网络助手 Cargo 版本统一为 0.4.2。没有创建 GitHub Release。

## 修复：扫描到开发板后“读取机器人 SSH 主机密钥失败：”且无原因

扫描能在开发机网口没有 IPv4 的情况下找到开发板，但 SSH 需要开发机网口与开发板处于同一网段。未配置时，去往开发板的流量会走默认路由（通常是 Wi-Fi），`ssh-keyscan` 超时且不输出任何信息，于是错误提示后面是空的。

- 读取主机密钥失败时，按 `ip route get` 判断原因：没有路由、走网关、走无线网卡，还是直连但 SSH 无响应，并给出下一步操作。
- 发现列表里路由未就绪的 IPv4 候选，按钮改为“配置本机 IP 后添加”：先配置临时地址，成功后直接弹出“添加 SSH 目标”。

## 修复：切换 Wi-Fi 后直连网线的临时地址丢失、流量改走无线网卡

**原因**：之前用 `ip address add` 给网口加临时地址，NetworkManager 并不知道这个地址。直连网口上通常还挂着 NetworkManager 的默认 DHCP 连接（如“有线连接 1”），开发板不提供 DHCP，它会超时、重试并重新激活设备；切换 Wi-Fi 等网络变化也会触发重新激活。每次重新激活，NetworkManager 都会清空它不认识的地址，去往开发板的流量于是改走 Wi-Fi 的默认路由。已在容器中用 NetworkManager 1.46 复现：手动地址在 DHCP 超时后约 15 秒被清掉。

**修复**：网口由 NetworkManager 管理时，网络助手改为创建并启用一个只存在内存、不写入磁盘的连接 `robolink-<网卡名>`：手动 IPv4、`never-default`（永不成为默认路由）、不改 DNS、IPv6 仅 link-local，autoconnect 优先级 100。同一网口的多个 RoboLink 地址合并在这个连接里。清理时删除该连接，网口恢复原来的连接。NetworkManager 未运行或网口未被管理时仍使用 `ip address add`。

已在容器中用 NetworkManager 验证：配置后设备断开再连接，地址仍在、路由仍走网线；清理后临时连接被删除。

注意：可选的直连 DHCP Server 仍用 `ip address add` 配置本机地址，同样可能被 NetworkManager 清掉，后续版本再处理。
