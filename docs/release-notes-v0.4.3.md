# RoboLink v0.4.3 测试候选

修复 v0.4.2 实测中的三个连接问题。远程桌面另行开发。

## 断线后无法重新验证指纹 / 输入系统密码后跳到终端页

**原因**：每当当前 SSH 终端会话结束，前端就调用 `cleanup_session_network_addresses`，通过 pkexec 删除本机临时直连地址（`robolink-<网口>`）。

- 点 Wi‑Fi 连接、蓝牙配对或重新连接时，代码先关闭旧终端，但当时 `activeTerminalRef` 仍指向旧会话，旧会话的退出事件被当成当前会话结束：弹出系统授权（pkexec）密码框 → 删除直连地址 → 页面跳到终端 → 新会话因为地址没了立即断开。
- 网线抖动或 SSH 心跳超时也会走同一条路径；地址被删后 `ssh-keyscan` 去不了开发板，于是无法再读取 / 核对指纹。

**修复**：

- SSH 会话结束（断线、`exit`、切换 Wi‑Fi、点“断开”）不再删除直连地址，可直接重新连接。
- 关闭旧会话前先清空当前会话 id，旧会话的退出事件不会再误伤新会话。
- “临时”地址改为 **退出 RoboLink 时清理**；勾选“保持”的地址仍需手动清理。列表里的单条清理 / 全部清理照常可用。

## 扫描蓝牙 / Wi‑Fi、点击连接经常没反应

- 远程命令增加本机 25 秒超时。之前只有机器人端的 `timeout 18s`，链路半断时本机 ssh 会一直等到心跳超时（约 45 秒），期间全局忙碌状态让所有按钮变灰。
- Wi‑Fi / 蓝牙扫描使用各自的“扫描中”状态，不再锁住其他按钮。
- SSH 未登录或已断开时，扫描和蓝牙操作直接提示“先到终端页连接”，不再静默失败；后台命令遇到 `Permission denied` 时也给出同样提示。
- 蓝牙：不再把 `bluetoothctl` 的错误丢进 `/dev/null`。权限不足、没有适配器、bluetoothd 未运行时会在蓝牙页显示原因和处理建议（之前会显示成“已关闭”，扫描按钮被禁用）。设备详情改为一次 SSH 取回（最多 30 台），扫描时间从 8 秒改为 6 秒；“已配对”以 `bluetoothctl info` 为准，兼容不支持 `devices Paired` 的旧版 BlueZ。
- Wi‑Fi 扫描：先单独请求 `nmcli device wifi rescan`，被 polkit 拒绝时仍返回缓存列表，并提示可在终端用 sudo 重新扫描。
- Wi‑Fi 连接、蓝牙配对：在终端执行失败后提示“按回车用 sudo 重试”，sudo 密码只在机器人终端里输入，不经过 RoboLink。

## 仍需实测确认

- 以太网偶发掉线：如果开发机用的是 USB 网卡（`enx…`，多为 r8152），请在掉线后执行 `journalctl -k --since "10 min ago" | grep -iE 'r8152|link'`，看是否有 USB 自动挂起或链路 down/up。
