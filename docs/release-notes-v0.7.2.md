# RoboLink v0.7.2 · Ubuntu 22.04

## 开发板和电脑 Wi‑Fi 在同一网段时也能直连
- 例如开发板是静态地址 192.168.11.50，而电脑连的 Wi‑Fi 也是 192.168.11.x。以前 RoboLink 为了不抢 Wi‑Fi 的路由，会拒绝配置本机地址，结果连不上。
- 现在「自动配置本机 IP 并添加」和「一键直连」遇到这种情况，会只给这台开发板加一条走网线的主机路由：网线网卡上加一个 /32 地址（例如 192.168.11.254/32），到 192.168.11.50 的流量走网线，同网段的其他地址仍然走 Wi‑Fi，上网不受影响。
- 本机地址会避开路由器（网关）、Wi‑Fi 上已经通信过的设备，并先在网线上检查没人占用。
- 清理「RoboLink 添加的地址」时，这条主机路由会一起删除。
- 注意：如果 Wi‑Fi 网络里恰好也有一台设备用着同一个地址（例如 192.168.11.50），配置后电脑只能访问网线上的开发板。

# RoboLink v0.7.1 · Ubuntu 22.04

## 修复：连到开发板只是“请求中”的地址
- 开发板从别的网络（比如路由器）拿过地址后接到电脑上，会一直广播 DHCP 请求“我还想要这个地址”。之前 RoboLink 把请求里的地址当成可以连接的候选，还会自动给本机配同网段地址，结果连接时没有 ARP 应答。
- 现在这类候选会标成「开发板正在请求这个地址，还没有拿到」，按钮改为「启动直连 DHCP」。
- 一键直连遇到这种情况，会说明原因并直接询问是否启动直连 DHCP，等开发板拿到地址后自动再找一次。
- 连接时如果保存的地址没有 ARP 应答，会先按 MAC 找开发板的新地址（不需要授权），找到就自动改地址并继续连接；找不到再询问是否重新寻找。

# RoboLink v0.7.0 · Ubuntu 22.04

这一版集中改进网线直连：认设备不认 IP、一键连上、不再依赖终端、断线自己连回来。

## 设备按 MAC 识别，指纹跟着设备走
- 每台机器人会记住它的 MAC（有线、无线可以各记一个）。开发板换了 IP 后，重新发现时会按 MAC 认出它，并自动更新保存的地址。
- SSH 主机指纹改为按设备固定，不再按「IP:端口」固定。同一块板子换 IP 不用重新核对指纹；另一块板子占了原来的 IP 时会被拦下，并提示「这个地址现在是另一台设备」。
- 旧版本保存的指纹在第一次启动时自动迁移，不需要重新核对。

## 一键直连
- 设备总览和网络页新增「一键直连」：检查网线、发现开发板、给本机网口挑一个不冲突的地址、连接，一次点完。
- 本机地址自动选择：普通网段用 /24，169.254 用 /16；添加前检查地址冲突和路由重叠，添加后如果路由没走这张网卡会自动撤销。
- 大约 10 秒内没有发现设备时，会询问是否在这张网卡上启动直连 DHCP，然后自动再找一次。
- 系统授权弹窗在几分钟内只出现一次（新增 polkit 规则），发现和配置地址不再各问一遍密码。
- 候选设备上的「配置本机 IP 后添加」改为自动配置；自动失败时仍会打开原来的手动窗口。

## 免密连接，页面不再依赖终端
- 第一次登录成功后，可以一键启用免密连接：RoboLink 生成自己的密钥，把公钥加到开发板的 `authorized_keys`。私钥只保存在本机。
- 启用后，服务、Wi-Fi、蓝牙、音频等页面直接用这把密钥在后台连接，不需要先打开终端登录；终端只用来交互。
- 可以随时在「设备总览 → 快速调试 → 免密连接」里关闭，关闭时会从开发板移除公钥。
- 没有启用时和以前一样，沿用终端里的登录。

## 断线自动恢复
- 拔掉网线几秒内就能发现（以前要等 SSH 超时约 45 秒）；插回后马上重新寻找开发板。
- 断线后按 MAC 重新找到开发板，IP 变了会自动更新；启用了免密连接时会自动连回，并恢复终端。没有启用时，板子回来后会自动打开终端等你输入密码。
- 新增「重启开发板」和「关机」，执行后显示等待提示，开发板回来后自动重新连接。

## 板端诊断
- 「诊断记录」页新增「采集板端诊断」：一次收集 journalctl、dmesg、磁盘、内存、温度、`ip a`、路由、nmcli、rfkill 和失败的服务，保存到本机 `~/RoboLink-diagnostics/`，并可在窗口里查看和复制。

## 这一版还没做
- 开发板和本机其他网络同网段时的冲突处理（按主机路由绑定网卡）。
- SFTP 传文件和多终端会话。
- 直连 DHCP 的租约表、拔线后自动停止 DHCP。
- mDNS 主机名解析、自定义扫描网段、取消扫描。
