# RoboLink 产品与开发规格

## 产品方向

RoboLink 是 Linux 开发机上的机器人调试台，面向没有显示器和键盘的 Linux 机器人。开发机与机器人用一根网线直接连接，不经过路由器或交换机。机器人 Wi-Fi 属于远端控制对象，与开发机直连接口分开管理。

产品仅提供 GUI 工作流，不实现面向用户的 CLI。GUI 在“网络与 Wi-Fi”页面完成网卡选择、策略选择、设备发现、候选验证、临时地址、可选 DHCP、状态查看、清理和 SSH 目标添加。当前开发版本为 **v0.4.3**，包含一次性远端 sudo 授权和 Wi-Fi SSH 回程保护；真实硬件验收仍待用户完成。

## 设备发现策略

可扩展的策略选择和后端编排在现有项目中实现，不另建一套应用。接口选择为空表示所有物理有线接口，或由用户指定一个接口。每个候选保留本机接口、IP、MAC、证据和验证状态，不按 MAC 相似性合并设备。

| 原需求 | 当前策略与边界 |
|---|---|
| A · 被动发现 | 分别选择 ARP、DHCP Discover/Request、IPv6 ND、mDNS。监听 8 秒，在每张接口独立收集报文。ARP Request/Reply、Gratuitous ARP、Probe 分开；DHCP 拟请求地址、IPv6 DAD 与实际源地址分开。mDNS 仅把报文源作为证据。 |
| B · 主动验证 | 对候选 IPv4 做定向 ARP；有正确接口路由时，可选 ICMP 辅助和单个 TCP 端口。默认端口 22，可自定义；不把 Ping 失败等同离线，不把 TCP 开放等同 SSH 身份已验证。 |
| C · DHCP | 用户明确选择接口并确认后，启动本应用拥有的单接口 dnsmasq 实例。默认关闭，不随扫描强启；支持查看、启动、停止和异常退出后清理。 |
| D · Link-local | IPv4 169.254/16 报文/邻居候选；IPv6 Link-local 报文、受限链路探测和邻居候选。IPv6 `%接口` scope 贯穿候选、端口验证和 SSH。不遍历整个 IPv4 /16。 |

普通 ARP 目标不能直接认作发包设备 IP；`0.0.0.0` ARP Probe 目标仅标候选。DHCP Discover 可能没有可用 IPv4，此时提示可选 DHCP，而不是捏造地址。ND 查询第三方目标不是发包者身份。旧邻居项仅为缓存证据，需要重新验证。

被动策略优先低干扰；主动操作由 GUI 选择。所有策略都有局限，不声称能发现任意静默、未知的静态 IP。无候选时可手动添加已知 IP/主机名，机器人仍须启用 SSH。

### 多网卡与物理链路

只枚举和抓取物理有线接口，包括常见 enp、eth、enx 和 USB 以太网。GUI 与 helper 使用同一 sysfs `carrier` 物理链路来源，不再依赖 sysfs flags 中错误的链路位。枚举后拔线或单接口断开应跳过并显示原因，不应让其他网卡的扫描一起失败。

第一阶段仅支持不重叠子网的独立发现与连接。重复目标 IP、重叠子网、多路径设备识别、策略路由和 Network Namespace 属于第二阶段；不通过 MAC 相似性或单个 machine-id 擅自去重。

### 主动验证安全

ARP 仅针对收集到的候选，设数量和时间限制。ICMP 与 TCP 验证必须确认地址路由对应选定网卡；TCP 绑定相应源地址，IPv6 Link-local 使用接口 scope，避免误走 Wi-Fi 或其他接口。未选择探测、无可用路由、探测失败和探测成功分别展示。候选 IP、MAC 和端口不能替代 SSH 指纹。

## 本机配置与生命周期

### 附加 IPv4

有正确接口路由时直接验证，无路由时由 GUI 提议附加地址并要求用户明确确认。helper 检查地址格式、本机现有地址、子网边界、路由重叠和重复地址，之后只执行精确的地址添加。ARP 通常不能得知真实掩码，普通 `/24` 是可编辑假设，IPv4 Link-local 用 `/16`。

不覆盖本机已有地址、默认路由、DNS、Wi-Fi 或防火墙，也不修改机器人 IP。v0.4.3 机器人 Wi-Fi 操作会单独在机器人内存路由表中保护当前 SSH 客户端回程；详见“权限与错误分类”。

### 可选 DHCP

采用单接口服务实现而非 NetworkManager `shared`，因此不创建/删除用户 NetworkManager 连接。记录本应用独立 ID、调用用户、接口、进程身份、配置和本机附加地址，状态存储在受保护的 root 运行目录中。只有本应用记录且身份匹配的进程可停止；不能按进程名终止系统 dnsmasq。

启动前拒绝已存在的 DHCP 服务/端口冲突，并检查本机地址和路由。地址使用用户选择的私有 `/24`，默认本机 `192.168.77.1/24`。采用 `leasefile-ro`，不读写全局租约文件；本应用专属受保护日志中的 DHCPACK 仅作为待复验缓存候选，不能当作存活或 SSH 身份。默认只用于 SSH 直连：不提供默认网关和 DNS、不设置转发或防火墙、不共享 Internet。用户须确认接口没有接入共享 LAN。机器人 DHCP 客户端对租约的行为和旧路由仍需实机验证，不能保证固件网络行为不变。

提供启动、停止/清理和状态查询；未查询不等于服务关闭。GUI 异常退出后，通过自身运行记录找回服务和精确地址；停止/回滚失败不能假称成功。不自动删除或接管系统原有配置。

## 其他既有功能

- Tauri 2 + React + TypeScript 桌面 UI，浅色/深色，多目标 SSH。
- OpenSSH 首次核验并固定一把主机密钥及算法；后续密钥变化或旧版多 key pin 阻断，不静默升级信任。密码不持久化、不记入诊断日志。
- 机器人概览、systemd 服务启停、NetworkManager Wi-Fi 管理、BlueZ 扫描/配对/连接、PipeWire/PulseAudio 默认设备与音量、440 Hz 扬声器测试音。
- 单独展示 ALSA 硬件 PCM 清单，不假装可通过 pactl 调整；不录音、不读取或传输麦克风 PCM。
- 交互式 SSH PTY、高风险命令确认、多行粘贴预览。它们不是完整命令沙箱；用户仍需检查目标和输入。

## 权限与错误分类

整个 GUI 不以 root 运行。本机抓包与地址配置由受限 helper 和系统授权代理执行；机器人端 Wi-Fi、蓝牙、systemd 变更在用户明确确认后使用一次性 SSH sudo 密码，密码仅经 SSH 标准输入传输，不放进命令参数、配置文件或日志。Wi-Fi 操作只为当前 SSH 客户端添加精确运行期主机路由，经现有有线出口回包；默认路由、DNS 和既有不同静态主机路由不改，不提供通用 root shell。

界面区分本机系统授权/助手错误、机器人 sudo 认证错误和已授权后的实际操作失败；无设备、无物理链路、接口被跳过、地址冲突或路由不符不应统称授权失败。

## 构建与验收

面向 Ubuntu 22.04.5 amd64，在 Jammy 用户空间构建 Debian 测试包，检查 GLIBC 和系统依赖。自动化覆盖 TypeScript 构建、Rust 单元测试和静态检查：协议解析与截断报文、ARP source/probe 区分、DHCP 与 ND 候选、scope 校验、接口跳过、选项校验、授权分类、地址/路由冲突和 DHCP 所有权逻辑。

自动化与界面模拟均不代替真机。真实板子必须验证：原 RDK 静态地址流程；DHCP 获取与停止；两类 Link-local；自定义 SSH 端口；禁用 ICMP 仍能 TCP/SSH；多接口插拔；Session/Persistent；异常退出恢复；切换机器人 Wi-Fi 后当前 SSH 回包仍走有线、机器人互联网默认出口仍按 Wi-Fi 连接工作，且既有冲突路由会安全停止。未获得真实机器人前，不把上述硬件项标记通过。

浏览器默认入口仅演示 UI，不表示真实设备状态。详细用户操作见[第一次直连 Linux 机器人](first-direct-connection.md)。当前没有 USB gadget 初始化、串口控制台、ROS 专属诊断、容器管理、网络流量图、更新器或 Windows/macOS 构建。

DHCP 配置语义以 [dnsmasq 官方手册](https://thekelleys.org.uk/dnsmasq/docs/dnsmasq-man.html) 为依据：空 `dhcp-option=3/6` 抑制默认网关/DNS 选项，`port=0` 禁止 DNS 服务，`bind-interfaces` 限定接口，`leasefile-ro` 不创建、读取或写入租约数据库文件。实际系统与机器人端的行为仍需真机验收。
