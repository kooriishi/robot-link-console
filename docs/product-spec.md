# RoboLink 产品与开发规格

## 产品方向

RoboLink 是运行在 Linux 开发机上的机器人调试控制台，面向没有外接显示器、键盘和鼠标的 Linux 机器人。核心任务是从开发机发现并连接机器人，快速检查服务与外设，必要时进入 SSH 终端排障。

**有线网络是开发机与机器人直接点对点相连，不经过交换机、路由器或其他中间设备。** 开发机的直连接口与机器人内部的 Wi-Fi 是两个独立控制对象，界面必须分别说明。

## 第一版原型范围

仓库当前提供 React + TypeScript 的交互式界面原型，数据均为演示数据。页面可以切换、筛选区域可输入、服务/Wi-Fi/蓝牙/音频控件可触发本地演示反馈，终端仅模拟少量只读输出；**不会建立 SSH 连接，不会扫描或修改网卡，不会操作真实 systemd、Wi-Fi、蓝牙或音频设备。**

原型页面：

- **设备总览**：直连拓扑、机器人状态、关键服务和快速入口。
- **网络与 Wi-Fi**：分开展示开发机 ↔ 机器人直连以太网与机器人 Wi-Fi。
- **系统服务**：运行状态、启停、自启及后续日志入口。
- **蓝牙设备**：适配器状态、已配对设备、扫描和配对入口。
- **音频设备**：麦克风/扬声器选择、电平/音量和测试入口。
- **终端**：醒目显示目标主机和权限；演示命令不会执行。
- **诊断记录**：事件列表和脱敏诊断包入口。

## 建议的关键用户流程

### 首次直连

1. 用户选择明确的一张开发机有线网卡；界面展示设备名、MAC/IP、链路状态，并确认该网卡确实直连机器人。
2. 先读取现有地址和链路状态，并用低风险方式发现设备（优先 mDNS/机器人广播）；不默认做全网段扫描。
3. 列出候选机器人、地址和发现来源，由用户选择后再发起 SSH 连接。
4. 首次连接展示 SSH 主机指纹供核验；用户确认后固定该指纹，变化时阻断连接并警告。
5. 发现失败时逐步提示链路、地址、机器人端 SSH 和防火墙诊断；不要擅自改配置。

### 直连地址恢复

机器人和开发机可能没有 DHCP。先显示双方实际地址；若无可用地址，提示手动设置方式或提供“配置所选直连接口”的高级流程。任何地址配置都必须逐项预览变更前后值、作用接口和失联风险，并提供超时自动回滚/恢复路径。可将链路本地地址作为候选方案，但不能假设两端一定已获得互通地址。

### 外设与服务

- 系统服务分开提供查看、启动、停止、重启；操作前说明目标主机和影响，默认不自动提权。
- 修改机器人 Wi-Fi 前明确警告该操作可能中断当前 SSH；若有有线直连仍可达，应说明这一点，但不保证机器人网络设置正确。
- 蓝牙配对必须由用户确认；配对、连接和设为音频路由分别反馈状态。
- 修改默认音频输入/输出后提供测试与恢复路径，说明可能影响正在运行的 ROS/语音节点。

## 信息架构 / 页面

| 页面 | 主要内容 | 主要动作 |
|---|---|---|
| 设备总览 | 目标主机、直连链路、健康指标、关键服务 | 进网络/服务/终端 |
| 网络与 Wi-Fi | 直连网卡、机器人网络、机器人 Wi-Fi | 重新发现、连接、配置预览 |
| 系统服务 | systemd 服务、状态、自启、日志 | start / stop / restart |
| 蓝牙设备 | hci 适配器、附近设备、配对设备 | scan / pair / connect / forget |
| 音频设备 | 输入、输出、默认路由、电平和音量 | 选择、测试录音/播放 |
| 终端 | 本地/远端标识、主机、用户、权限、输出 | SSH Shell、复制、清屏 |
| 诊断记录 | 操作事件、错误与时间戳 | 搜索、脱敏导出 |

## P0 安全与可靠性要求

1. **开发机网络默认只读**：不改 Wi-Fi、默认路由、DNS、DHCP、防火墙、网卡优先级；高级配置仅操作用户明确选择的直连接口。
2. **可逆网络操作**：展示变更对照；配置后若失联应在可配置超时后回滚，且不影响其他接口。
3. **SSH 身份验证**：优先使用系统 OpenSSH Agent/密钥；核验并固定主机指纹；指纹变化默认拒绝。
4. **凭证保护**：不在普通配置和日志保存私钥/密码；Wi-Fi 密码输入时隐藏并尽量不持久化；诊断导出自动脱敏。
5. **终端边界**：显著区别本机和机器人；远端命令不默认 sudo；关机、重启、磁盘、网络、删除等高风险命令需显示主机与命令并二次确认；多行粘贴先预览，不擅自执行。
6. **明确状态**：区分“链路已连接”“SSH 已验证”“机器人 Wi-Fi 在线”和“服务健康”，不可混为一个“在线”状态。
7. **可恢复连接**：有限次数重试、停止重试、保留最后成功地址；按步骤引导重新发现。

## 技术实现建议

- **前端**：当前 Vite + React + TypeScript 桌面端风格界面，后续保留为 Tauri 2 前端。
- **Linux 桌面外壳**：建议 Tauri 2（优先），提供 Linux AppImage/deb；安装与打包尚未纳入本次原型。
- **SSH**：优先使用系统 OpenSSH（Agent、known_hosts、ProxyJump 等可复用），通过受限的后端命令封装和明确输入校验调用。不要拼接未转义 shell 字符串；批量诊断命令由固定模板构造。
- **设备控制**：经 SSH 执行受控子命令；读取 NetworkManager/systemd/BlueZ/PipeWire/PulseAudio 状态时，先检测发行版与可用工具，并显示不支持原因。
- **发现**：用户选择的有线网卡上优先 mDNS/UDP 广播；必要时用户显式触发且限速的子网发现。不要扫描非选定网络。
- **状态更新**：连接状态与实时遥测使用可取消的任务/事件通道，明确时间戳和过期状态。

## 迭代建议

- **M0（当前）**：交互式前端原型、UI 信息架构、需求与安全规格。
- **M1**：Linux 桌面壳与 SSH 连接；主机收藏、指纹校验、只读诊断；真实设备上手动验证。
- **M2**：服务状态/日志和受确认的启停；连接历史、脱敏导出。
- **M3**：直连接口发现与可回滚的地址配置；NetworkManager 适配。
- **M4**：Wi-Fi / BlueZ / PipeWire 控制、设备测试与失联恢复。

## 验收标准（M1 起）

- Linux 上可安装/启动；目标连接断开时不影响开发机现有网络。
- 用户清楚看到“开发机 ↔ 机器人直连”，且能区分机器人 Wi-Fi。
- 首次 SSH 连接经过指纹核验；更换指纹时阻止连接。
- 任何网络变更显示作用接口与回滚方案；未确认时不执行。
- SSH 凭证不出现在日志、导出诊断包或普通明文配置中。
- 终端始终显示主机/用户/权限，危险操作可识别、确认、记录。
